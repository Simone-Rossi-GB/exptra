  1. PC scrauso con PocketBase

  Cosa significa "server"?

  Un server è semplicemente un computer che risponde a richieste. Il tuo PC vecchio diventa un
  server quando fa girare un programma (PocketBase) che ascolta le connessioni in arrivo.

  Come funziona PocketBase?

  PocketBase è un singolo file eseguibile (circa 20-30 MB) che contiene:
  - Un database SQLite (dove vengono salvati i dati)
  - Un'interfaccia admin web (per gestire collezioni, utenti, ecc.)
  - Un server API REST (che risponde alle richieste HTTP)
  - Sistema di autenticazione integrato

  Setup passo-passo:

  a) Scegliere il sistema operativo per il PC scrauso

  Opzione A: Windows (se già ce l'hai)
  - Pro: Familiare, facile da usare
  - Contro: Più pesante, consuma più risorse

  Opzione B: Linux Ubuntu Server (consigliato)
  - Pro: Leggerissimo, perfetto per PC vecchi, gratis
  - Contro: Usa la riga di comando (ma è facile)

  b) Installare PocketBase su Windows:

  1. Vai su https://pocketbase.io/docs/
  2. Scarica il file per Windows (es: pocketbase_0.X.X_windows_amd64.zip)
  3. Estrai in una cartella, ad esempio C:\pocketbase\
  4. Dentro trovi un file pocketbase.exe

  c) Avviare PocketBase:

  Apri il Prompt dei comandi (CMD) nella cartella:
  cd C:\pocketbase
  pocketbase.exe serve

  Cosa succede:
  - PocketBase si avvia sulla porta 8090
  - Crea automaticamente una cartella pb_data (dove salva il database)
  - Puoi accedere all'admin panel su http://localhost:8090/_/

  d) Configurazione iniziale:

  Quando apri http://localhost:8090/_/ per la prima volta:
  - Ti chiede di creare un admin (email + password)
  - Questo è l'account per gestire il backend

  e) Creare la collezione "spese":

  Dall'admin panel:
  1. Vai su "Collections" → "New Collection"
  2. Nome: spese
  3. Tipo: Base (non Auth)
  4. Aggiungi campi:
    - descrizione (tipo: Text)
    - importo (tipo: Number)
    - data (tipo: Date)
    - user (tipo: Relation → users) ← importante per separare gli utenti

  f) Configurare le regole di accesso (API Rules):

  Questo è fondamentale per la sicurezza:

  Per la collezione "spese":
  - List/Search rule: @request.auth.id != "" && user = @request.auth.id
    - Significato: "Puoi vedere solo le tue spese se sei loggato"
  - View rule: @request.auth.id != "" && user = @request.auth.id
  - Create rule: @request.auth.id != ""
  - Update rule: @request.auth.id != "" && user = @request.auth.id
  - Delete rule: @request.auth.id != "" && user = @request.auth.id

  g) Far partire PocketBase automaticamente all'avvio:

  Su Windows:
  1. Crea un file start-pocketbase.bat:
  cd C:\pocketbase
  pocketbase.exe serve
  2. Metti il collegamento nella cartella Avvio:
    - Premi Win+R, digita shell:startup
    - Copia il .bat lì dentro

  Su Linux:
  Usi systemd (un gestore di servizi), ma te lo spiego se scegli Linux.

  2. Router Port Forwarding

  Cosa significa?

  Immagina il tuo router come il portiere di un condominio:
  - Rete locale (LAN): il condominio, con indirizzi tipo 192.168.1.x
  - Internet (WAN): la strada, con l'indirizzo pubblico del condominio
  - Port forwarding: dire al portiere "quando qualcuno chiede la porta 8090, mandalo
  all'appartamento 192.168.1.100"

  Come funziona la rete:

  [Internet]
      ↓
  [Il tuo IP pubblico: es. 93.45.123.456]
      ↓
  [Router a casa tua]
      ↓
  [Rete locale 192.168.1.x]
      ├── PC scrauso: 192.168.1.100 (PocketBase sulla porta 8090)
      ├── Tuo PC: 192.168.1.50
      └── Telefono: 192.168.1.51

  Configurare il Port Forwarding:

  Passo 1: Trovare l'IP locale del PC scrauso

  Su Windows:
  - Apri CMD
  - Digita ipconfig
  - Cerca "Indirizzo IPv4": es. 192.168.1.100

  Su Linux:
  - Digita ip addr
  - Cerca inet 192.168.1.xxx

  Passo 2: Assegnare IP statico al PC scrauso

  Perché? Altrimenti il router potrebbe cambiare l'IP locale (DHCP) e il port forwarding smette di     
  funzionare.

  Metodo 1 - Dal router (consigliato):
  1. Accedi al router (vedi sotto)
  2. Cerca "DHCP Reservation" o "IP statico"
  3. Associa l'indirizzo MAC del PC all'IP (es. 192.168.1.100)

  Metodo 2 - Dal PC:
  Configuri manualmente l'IP nelle impostazioni di rete.

  Passo 3: Accedere al router

  Ogni router è diverso, ma il processo è simile:

  1. Trova l'IP del router:
    - Windows: ipconfig → cerca "Gateway predefinito" (es. 192.168.1.1)
    - Linux: ip route → cerca "default via"
  2. Accedi via browser:
    - Vai su http://192.168.1.1 (o l'IP trovato)
    - Ti chiede username e password
  3. Credenziali comuni:
    - admin / admin
    - admin / password
    - Spesso sono scritte su un'etichetta sotto il router
    - Cerca il modello del tuo router online per le credenziali di default

  Passo 4: Configurare la regola di Port Forwarding

  Cerca nel menu del router:
  - "Port Forwarding"
  - "Virtual Server"
  - "NAT"
  - "Applicazioni e Gaming"

  Crea una nuova regola:
  - Nome: PocketBase (o come vuoi)
  - Porta esterna: 8090
  - IP interno: 192.168.1.100 (il PC scrauso)
  - Porta interna: 8090
  - Protocollo: TCP (o TCP/UDP)

  Salva e applica.

  Passo 5: Testare

  1. Trova il tuo IP pubblico:
    - Vai su https://whatismyipaddress.com/
    - Annota l'IP (es. 93.45.123.456)
  2. Testa dal telefono (dati mobili, non WiFi!):
    - Apri il browser
    - Vai su http://93.45.123.456:8090/_/
    - Dovresti vedere l'admin panel di PocketBase

  Perché dal telefono con dati mobili? Perché se usi il WiFi di casa sei già dentro la rete locale,    
   quindi non testi il port forwarding.

  3. DynDNS (DNS Dinamico)

  Il problema:

  Il tuo IP pubblico cambia periodicamente. Il tuo ISP (TIM, Vodafone, Fastweb...) ti assegna un IP    
   diverso ogni tot giorni/settimane.

  Esempio:
  - Oggi: 93.45.123.456
  - Domani dopo un riavvio del router: 93.45.200.789

  Se distribuisci l'app con l'IP hardcoded, dopo qualche giorno smetterà di funzionare!

  La soluzione: DynDNS

  DynDNS ti dà un nome di dominio (es. exptra.duckdns.org) che punta sempre al tuo IP pubblico,        
  anche quando cambia.

  Come funziona:
  1. Ti registri su un servizio DynDNS (gratis)
  2. Ottieni un dominio tipo exptra.duckdns.org
  3. Installi un piccolo programma sul PC che controlla l'IP pubblico ogni 5 minuti
  4. Se l'IP cambia, il programma aggiorna automaticamente il DNS

  Servizi DynDNS gratuiti:

  1. DuckDNS (il più semplice)
    - Sito: https://www.duckdns.org/
    - Domini: tuonome.duckdns.org
    - Limite: 5 domini gratis
  2. No-IP
    - Sito: https://www.noip.com/
    - Domini: tuonome.ddns.net
    - Limite: 3 domini gratis (devi confermare ogni 30 giorni)
  3. Afraid.org
    - Domini con molte estensioni
    - Più complesso da usare

  Setup DuckDNS (passo-passo):

  Passo 1: Registrazione

  1. Vai su https://www.duckdns.org/
  2. Fai login con GitHub, Google, ecc. (non serve registrazione)
  3. Scegli un nome, es. exptra
  4. Ottieni il dominio exptra.duckdns.org
  5. Copia il token (una stringa tipo a7c4f4e8-6f5d-4f9e-8f4b-1234567890ab)

  Passo 2: Installare il client sul PC scrauso

  Su Windows:
  1. Crea una cartella C:\duckdns\
  2. Crea un file duck.bat:
  echo url="https://www.duckdns.org/update?domains=exptra&token=TUO_TOKEN&ip=" | curl -k -o 
  C:\duckdns\duck.log -K -
  3. Testa eseguendo il .bat (dovrebbe creare duck.log con "OK")
  4. Crea un'attività pianificata (Task Scheduler):
    - Apri "Utilità di pianificazione"
    - Crea attività → Esegui duck.bat ogni 5 minuti

  Su Linux:
  Aggiungi un cron job (più semplice).

  Passo 3: Verificare

  1. Vai su https://www.duckdns.org/ (fai login)
  2. Dovresti vedere il tuo IP pubblico accanto a exptra.duckdns.org
  3. Prova a visitare http://exptra.duckdns.org:8090/_/

  Adesso puoi usare exptra.duckdns.org nell'app invece dell'IP!

  4. HTTPS (Certificato SSL)

  Perché serve HTTPS?

  Con HTTP (senza la 'S'):
  - I dati viaggiano in chiaro su internet
  - Chiunque può intercettare password, dati personali, ecc.
  - I browser moderni mostrano "Non sicuro"

  Con HTTPS:
  - I dati sono crittografati
  - Serve un certificato SSL (che conferma l'identità del server)

  Il problema:

  PocketBase usa solo HTTP. Per aggiungere HTTPS serve un reverse proxy (un intermediario tra
  internet e PocketBase).

  Reverse Proxy: Cos'è?

  [Internet HTTPS :443]
      ↓ (crittografato)
  [Reverse Proxy - Caddy/Nginx]
      ↓ (localhost, non crittografato ma sicuro)
  [PocketBase :8090]

  Il reverse proxy:
  - Riceve connessioni HTTPS dalla porta 443
  - Decripta i dati
  - Li gira a PocketBase su localhost:8090
  - Gestisce automaticamente il certificato SSL

  Opzione A: Caddy (SUPER FACILE - Consigliato)

  Caddy è un web server che:
  - Genera e rinnova automaticamente i certificati SSL (Let's Encrypt)
  - Si configura con 3 righe

  Setup Caddy:

  1. Installare Caddy su Windows:
  - Scarica da https://caddyserver.com/download
  - Estrai caddy.exe in C:\caddy\

  2. Creare il file di configurazione Caddyfile:
  exptra.duckdns.org {
      reverse_proxy localhost:8090
  }

  Questo significa: "Per tutte le richieste a exptra.duckdns.org, girile a localhost:8090 e
  gestisci tu l'HTTPS".

  3. Avviare Caddy:
  cd C:\caddy
  caddy run

  4. Port forwarding nel router:
  - Cambia la regola da porta 8090 → porta 443 (HTTPS)
  - Aggiungi anche porta 80 (HTTP, serve per il certificato)

  Regole router:
  - Porta 80 → 192.168.1.100:80
  - Porta 443 → 192.168.1.100:443

  5. Testare:
  - Vai su https://exptra.duckdns.org/_/
  - Dovrebbe funzionare con HTTPS! (lucchetto verde)

  Opzione B: Nginx + Certbot (Più complesso)

  Nginx è un web server più tradizionale.
  Certbot è un tool che genera i certificati Let's Encrypt.

  È più complesso da configurare, ma è lo standard in produzione. Se vuoi imparo più profondamente,    
   posso spiegarti anche questo, ma Caddy è più adatto per il tuo caso.

  Alternativa moderna: Cloudflare Tunnel (ZERO port forwarding!)

  Il problema del port forwarding:

  - Esponi il tuo IP pubblico
  - Apri porte nel router (rischio sicurezza)
  - Devi gestire firewall, DynDNS, ecc.

  Cloudflare Tunnel:

  Crea un tunnel sicuro dal tuo PC a Cloudflare, senza aprire porte!

  Come funziona:
  [Tuo PC] → (tunnel crittografato) → [Cloudflare] ← [Internet/Utenti]

  - Il PC si connette a Cloudflare (outbound, non serve port forwarding)
  - Cloudflare ti dà un dominio pubblico
  - HTTPS automatico
  - IP pubblico nascosto

  Setup (super facile):
  1. Account Cloudflare (gratis)
  2. Installi cloudflared sul PC
  3. Esegui: cloudflared tunnel --url http://localhost:8090
  4. Ti dà un URL tipo https://xxx.trycloudflare.com

  Pro:
  - Zero configurazione router
  - HTTPS gratis automatico
  - Più sicuro

  Contro:
  - Dipendi da Cloudflare
  - L'URL cambia ogni volta (a meno che configuri un tunnel persistente)

  2. HTTPS spiegato BENE (senza confusioni)

  Primo chiarimento: SSH ≠ SSL/TLS

  SSH (Secure Shell):
  - È per connettersi a terminale remoto
  - Esempio: ti connetti al Raspberry Pi con ssh pi@192.168.1.100
  - Usa coppie di chiavi (pubblica/privata)

  SSL/TLS (Secure Sockets Layer / Transport Layer Security):
  - È il protocollo usato da HTTPS
  - Cripta le comunicazioni web (browser ↔ server)
  - Usa certificati (non chiavi SSH!)

  Quando visiti un sito HTTPS, usi SSL/TLS, non SSH!

  ---
  Come funziona HTTPS (spiegazione dettagliata)

  Immagina HTTPS come una cassetta di sicurezza:

  Passo 1: Il server ha un "certificato"

  Il certificato è come una carta d'identità digitale che contiene:
  - Il dominio (es: exptra.duckdns.org)
  - Una chiave pubblica (chiunque può vederla)
  - La firma di un'autorità fidata (Let's Encrypt, Cloudflare, ecc.)

  Chi crea il certificato?
  - Let's Encrypt (gratis, è quello che usa Caddy)
  - Cloudflare
  - Altre "Certificate Authorities" (CA)

  Dove sta il certificato?
  Sul server (nel tuo caso, su Caddy che gira sul Raspberry Pi).

  Passo 2: Il client (browser) si connette

  Quando l'app Tauri si connette a https://exptra.duckdns.org:

  1. Richiesta iniziale (HTTPS Handshake):
  [App] → "Ciao, voglio connettermi in modo sicuro"
  [Server] → "Ecco il mio certificato + chiave pubblica"

  2. Verifica del certificato:
  Il browser/app controlla:
  - Il certificato è valido?
  - È firmato da un'autorità fidata? (Let's Encrypt è pre-installato nei browser)
  - Il dominio corrisponde? (exptra.duckdns.org)
  - Non è scaduto?

  3. Creazione della chiave di sessione:

  Questa è la parte magica! Il client (app):
  - Genera una chiave casuale (chiamata "session key")
  - La cripta usando la chiave pubblica del server (quella nel certificato)
  - La manda al server

  [App] → Genera chiave casuale: "abc123xyz"
  [App] → Cripta con chiave pubblica: "§$%&/()="
  [App] → Manda al server: "§$%&/()="
  [Server] → Decripta con chiave privata: "abc123xyz"

  Perché è sicuro?
  Solo il server può decriptare la chiave di sessione, perché:
  - La chiave pubblica può solo criptare
  - Solo la chiave privata (che sta sul server) può decriptare

  4. Comunicazione crittografata:
  Da questo momento, client e server usano la chiave di sessione (che conoscono solo loro) per
  criptare tutti i dati.

  [App] → "Dammi le spese" (criptato con abc123xyz)
  [Server] → "[{spesa1}, {spesa2}]" (criptato con abc123xyz)

  ---
  La tua domanda: "Come fa il client a sapere la chiave?"

  Risposta breve: NON la sa in anticipo! La ottiene durante l'handshake.

  Risposta dettagliata:

  1. Il certificato è pubblico: chiunque può scaricarlo
  2. La chiave pubblica è dentro il certificato: chiunque può vederla
  3. La chiave privata sta solo sul server: nessuno la conosce
  4. La chiave di sessione viene generata al momento: è diversa ogni volta

  Analogia:
  - Il certificato è come una cassetta postale con lucchetto
  - La chiave pubblica è il lucchetto (tutti possono chiuderci dentro qualcosa)
  - La chiave privata è l'unica chiave che apre il lucchetto (solo il server ce l'ha)
  - Tu (client) metti la chiave di sessione dentro la cassetta e chiudi il lucchetto
  - Solo il server può aprirla e leggere la chiave di sessione

  ---
  Quando viene rigenerata? Che succede?

  1. Rinnovo del certificato (ogni 90 giorni)

  Let's Encrypt rilascia certificati validi 90 giorni. Caddy li rinnova automaticamente ogni 60        
  giorni.

  Cosa succede quando si rinnova?
  - Caddy chiede un nuovo certificato a Let's Encrypt
  - Let's Encrypt verifica che tu controlli davvero il dominio
  - Viene generata una nuova coppia chiave pubblica/privata
  - Il nuovo certificato sostituisce quello vecchio

  Per il client/app cambia qualcosa? NO!
  - Il processo di handshake è identico
  - L'app scarica il nuovo certificato automaticamente alla prossima connessione
  - È completamente trasparente

  2. Chiave di sessione (ogni connessione)

  Viene rigenerata ogni volta che ti connetti!

  Connessione 1: chiave di sessione = "abc123"
  Connessione 2 (1 minuto dopo): chiave di sessione = "xyz789"

  Perché? Sicurezza! Se qualcuno intercetta una chiave di sessione, può decrittare solo quella
  specifica connessione, non tutte.

  In pratica, cosa devi fare?

  Setup HTTPS con Caddy (automatico):

  1. Installi Caddy sul Raspberry Pi
  2. Crei il Caddyfile:
  exptra.duckdns.org {
      reverse_proxy localhost:8090
  }
  3. Avvii Caddy:
  sudo caddy run

  Cosa fa Caddy automaticamente:
  - Contatta Let's Encrypt
  - Richiede un certificato per exptra.duckdns.org
  - Let's Encrypt verifica che tu controlli il dominio (via HTTP challenge sulla porta 80)
  - Caddy scarica il certificato
  - Ogni 60 giorni, Caddy rinnova il certificato in automatico
  - Tu non devi fare NULLA!

  Nell'app React/Tauri:
  // Prima (HTTP):
  const pb = new PocketBase('http://exptra.duckdns.org:8090')

  // Dopo (HTTPS):
  const pb = new PocketBase('https://exptra.duckdns.org')  // Porta 443 è implicita

  E basta! Il browser/app gestisce tutto il resto (handshake, verifica certificato, ecc.).

  3. Setup completo: Raspberry Pi + PocketBase + DuckDNS + Caddy

  Ecco il piano passo-passo:

  Hardware necessario:

  - Raspberry Pi 4 (2GB) o 3B+

  - Collega il Raspberry al router via Ethernet

  arp -a

  64.zip

  # Estrai
  unzip pocketbase_*.zip

  ./pocketbase serve --http="0.0.0.0:8090"

  Nota: Controlla la versione più recente su https://github.com/pocketbase/pocketbase/releases

  4. Creare un servizio systemd (autostart)

  sudo nano /etc/systemd/system/pocketbase.service

  [Unit]
  Description=PocketBase
  After=network.target

  [Service]
  Type=simple
  User=pi
  WorkingDirectory=/home/pi
  ExecStart=/home/pi/pocketbase serve --http="0.0.0.0:8090"
  Restart=always

  [Install]
  WantedBy=multi-user.target

  Attiva:
  sudo systemctl enable pocketbase
  sudo systemctl start pocketbase
  sudo systemctl status pocketbase

  sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https

  /usr/share/keyrings/caddy-stable-archive-keyring.gpg

  /etc/apt/sources.list.d/caddy-stable.list
  sudo apt update
  sudo apt install caddy

  6. Configurare Caddy

  sudo nano /etc/caddy/Caddyfile

  Contenuto:
  exptra.duckdns.org {
      reverse_proxy localhost:8090
  }

  Riavvia:
  sudo systemctl restart caddy

  - Porta 80 → 192.168.1.XXX:80 (Raspberry IP)

  [Internet]
      ↓
  [exptra.duckdns.org] ← DuckDNS punta al tuo IP pubblico
      ↓

  5. Caddy gira la richiesta a PocketBase (localhost:8090)
  6. PocketBase risponde con i dati
  7. Caddy cripta la risposta e la manda al client
